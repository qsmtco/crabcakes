# Documentation Updates

Based on recent conversation, update the relevant documentation file to capture new learnings, insights, or information worth preserving.

## Before Updating

1. Read the current document
2. Review what changed in this session
3. Identify what's worth adding or updating

## Update Guidelines

**Keep it current.** Update information in-place rather than appending historical notes. Remove outdated information instead of marking it as "previously..."

**Be terse.** High signal only. No filler words.

**Focus on:**
- High-level architecture and design
- Non-obvious patterns and conventions
- Key entry points
- Design decisions and rationale
- Critical dependencies
- References to related docs

**Skip:**
- Obvious information from source code
- Exhaustive function/parameter lists
- Step-by-step implementation details
- Low-level mechanics

**Preserve the document header** exactly as it exists.

## When to Update

Update if there's substantial new information that:
- Would be costly to re-discover
- Affects how others work with this codebase
- Captures an important decision or pattern

If nothing substantial changed, don't update.
