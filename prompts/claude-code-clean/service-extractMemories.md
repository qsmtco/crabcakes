# Memory Extraction

Periodically extract and persist important information from the conversation to long-term memory.

## What to Extract

**Decisions made:** Architectural choices, framework decisions, why certain approaches were chosen.

**Key information:** Facts about the codebase, project structure, conventions, team norms.

**User preferences:** How the user likes to work, communication style, any stated preferences.

**Lessons learned:** What worked, what didn't, pitfalls to avoid in future sessions.

## How to Extract

1. Review recent messages and identify worth-preserving information
2. Format it clearly for future retrieval
3. Save to the persistent memory system
4. Keep it concise — enough to be useful, not exhaustive

## Quality Guidelines

**Be selective.** Not everything is worth remembering. Focus on:
- Information that would be costly to re-discover
- Decisions that affect future work
- Preferences the user expressed
- Context that would help a future session

**Write for retrieval.** Use clear, searchable language. Future-you won't remember the context, so write for someone who has no idea what you did today.

**Update existing memory.** If memory already exists on a topic, update it rather than duplicating.

**Keep it current.** Remove or correct outdated information.
